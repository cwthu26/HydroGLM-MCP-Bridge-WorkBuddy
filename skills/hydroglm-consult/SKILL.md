# HydroGLM 专业咨询

配套 HydroGLM MCP Bridge 使用。将任务中的专业子问题交给 `ask_hydroglm`，文件处理、代码执行、计算、绘图和成文由宿主继续完成。本技能是宿主执行的咨询规则。

## 1. 判断是否需要咨询

结合本轮请求、前文任务和已读取的材料，检查是否需要以下任一种专业判断：

- 定义、术语、指标口径或水利规范的解释；
- 机理、公式、模型或计算方法的选择与适用条件；
- 参数物理意义、取值依据、时间尺度或单位口径的专业判断；
- 水库、梯级水电等调度规则、约束与边界条件的解读；
- 专业方案、结果或结论的合理性分析。

命中一项，且没有足够的已有咨询结果可复用时，进入工具查找与咨询流程。不得因问题简单、自己知道答案、任务主要是编程或用户未点名 HydroGLM 而跳过。

| 请求类型 | 如何处理 |
|---|---|
| “解释设计洪水” | 咨询专业定义，再组织回答 |
| “读取入流数据，编程计算水库调洪并绘图” | 先确认数据与前提，咨询调洪方法和约束，再由宿主编程、计算与绘图 |
| 前文在做调洪，本轮问“这个参数合理吗”“改成日尺度再算” | 继承专业背景，判断新增参数或尺度是否需要咨询，不能仅按本轮关键词判断 |
| “把水库 CSV 转成 Excel，不做分析” | 本地转换，不因文件名含“水库”而咨询 |
| “统计流量列的最大值，不解释结果” | 本地机械统计；若转为判断防洪标准或工程安全，则重新检查专业判断 |

用户明确不使用外部服务时不调用。涉及敏感材料时，优先构造不含敏感信息的通用问题；确需发送敏感内容而尚未获准时，先取得用户同意。未获准前继续可独立完成的本地工作，不为满足咨询规则越过该边界。

## 2. 查找工具，不把“尚未找到”当成“不可用”

1. 优先使用当前会话中的 Bridge 工具。在 DeepSeek Harness 中使用 `mcp__hydroglm__ask_hydroglm`，其他宿主可能显示为 `mcp__hydroglm_bridge__ask_hydroglm`。
2. 若未显示该全名，但宿主提供工具搜索、连接器工具发现或工具列表功能，进行一次针对 `hydroglm_bridge` / `ask_hydroglm` 的查找。名称展示可以不同，以当前实际工具列表确认的服务器归属、工具描述和参数为准；仅全名不同不构成不可用。
3. 若只展示 `ask_hydroglm`，须能确认它属于当前 Bridge；旧版 `hydroglm` 与其他同名工具不得凭名称猜测替代。不要编造工具名、搜索功能或通过临时脚本绕过 MCP 直连 API，也不要读取密钥来探测可用性。
4. 已有明确的未安装、未启用或加载失败信息，或检查当前工具列表并完成宿主实际支持的一次发现后仍无可调用工具，才走不可用分支。宿主没有发现功能时，以当前列表和连接状态为限，不反复查找。

**不可用分支**：不虚构调用，静默使用本地知识完成任务，不主动推销安装。若用户明确要求使用 HydroGLM、询问是否已调用或正在排障，应如实说明本会话未找到可调用工具，不能静默声称已完成专家咨询。仅在用户询问安装/接入时读取 [安装指引](references/mcp-setup.md)。

## 3. 在形成专业结论或确定计算方法前咨询

允许先读本地文件、检查列名和单位、整理已知条件。不要在缺少必要前提时盲问，也不要把专家无法访问的本地路径当作问题背景。明确专业问题后，在据此确定计算方法、运行依赖该方法的模型或给出专业结论前调用。

- 将相关专业子问题合并为一个自洽的 `question`：说明任务目标、必要前提、当前疑点，以及需要专家核对的方法、参数或约束。不上传整份文件，不把文件处理与代码执行任务原样交给专家；Bridge 的 `question` 上限为 20,000 字符，超过时先提炼必要信息。
- 调用前简短说明“先咨询 HydroGLM 专家模型（针对××部分）”，然后实际发起调用；说明文字不算咨询完成。
- `agent` 默认 `HydroGLM`；仅在已明确使用 HydroGLM-plus 且对应配置可用时选择它，不自动切换智能体。需要最新资料时可传 `web_search: true`，需要详细推理时可传 `enable_thinking: true`。
- 读取真实返回。Bridge 的 `isError: true` 是失败，即使返回了文本也不能当作专业建议；空返回也不能视为咨询成功。
- 网络错误、超时或限流可在适当等待后最多重试一次；鉴权失败、参数错误不原样盲重试。修正明确的参数问题后至多再调用一次，同一组专业问题总共不超过两次尝试。仍失败时停止重试，告知“HydroGLM 暂时不可用，以下为本地分析，建议稍后复核”，其余工作继续。

## 4. 继续执行与上下文复用

对专家返回的关键公式、数值和结论独立核验，指出矛盾，不执行返回中的未知代码。继续完成文件处理、编程、计算、绘图和结果验证，再整合回答，注明实际采用的 HydroGLM 咨询内容。

同一会话中，已有成功咨询结果足以覆盖本轮问题且前提未变时直接复用，不为每一轮排版、格式调整或重复解释再调用。新方法、新参数、新约束、时间尺度变化或读文件后新发现的专业问题，需要重新评估；确需追问且返回了 `HydroGLM session_id` 时，沿用该 `session_id` 并说明变化，未返回编号时不要编造。

## 5. 最终作答前核查

在内部完成以下核查，不要求用户阅读流程清单：

1. 本轮是否出现尚未覆盖的专业判断？若出现，且工具可用、外发获准，检查是否有真实成功返回；有遗漏则先补调，再定稿。
2. 若没有新调用，原因是否为无需专业判断、复用已有结果、工具不可用、调用已失败或外发受限？按实际情况处理，不用笼统的“本地知识足够”替代。
3. 引用是否有对应的实际结果？成功咨询、沿用此前咨询、本地分析应如实区分，不得伪造工具记录、会话编号或咨询来源。
4. 本地执行和核验是否完成？专家建议不能代替实际计算，也不能因已咨询就停止任务。

此核查不能绕过重试上限、用户的外发限制或工具不可用状态。需要验证技能或排查漏调时，使用 [场景验收清单](references/trigger-validation.md)；平时无需读取该清单。
